# 02. 시스템 아키텍처

## 1. 전체 흐름
```
[공공데이터포털 API / 사업안내 PDF]
        │ collect
        ▼
 data/raw ──► (L1) Rules-as-Code 컴파일러 ──► rules_db/{draft,review,approved}/*.yaml
                    │ LLM 추출 + 교차검증 + 자동 테스트
                    ▼
            rules/engine.py (평가기)  ◄──── rules_db/params/2026.yaml (기준값·출처)
               │                 │
               │                 └──► (L2) verify/ Z3 인코더 → 반례 가구(사각지대·절벽·중복)
               ▼
 [KOSIS 집계] ─► (L3) population/ 합성 가구 10만 ─► sim/static.py (전 가구 평가)
                                   │
                                   └─► agents/ 페르소나 200 × LLM 행동 → sim/behavior.py
               ▼
        (L4) redteam/  ──► 리포트
        (V)  backtest/ ──► 실제 수급 통계와 비교
               ▼
        api/ (FastAPI)  ◄──►  app/dashboard.py (Streamlit)
```

## 3. 핵심 모듈 책임
| 모듈 | 입력 | 출력 | 비고 |
|---|---|---|---|
| `rules/dsl.py` | YAML | `Program`(Pydantic) | 문서 04 |
| `rules/engine.py` | `Household`, `Program[]`, params | `Decision[]` | 순수 함수, 결정론적 |
| `verify/encoder.py` | `Program[]`, params | Z3 `Solver` | 문서 05 |
| `population/synth.py` | KOSIS 집계 | `households.parquet` | 시드 고정 |
| `agents/behavior.py` | 페르소나, 시나리오 | 신청 확률·근로 변화 | 응답 캐시 |
| `sim/scenario.py` | 현행/변경안 규칙 세트 | 지표 비교 | 대상자·실수급·재정 |
| `redteam/agents.py` | 변경안 | 공격 결과 | Z3 + LLM 혼합 |
| `backtest/run.py` | 과거 시나리오 | 예측 vs 실제 | 오차 지표 |

## 4. 설계 원칙
- **엔진은 결정론적**: LLM은 규칙 *작성*과 *행동 추정*에만 쓰고, 자격 판정 자체는 항상 코드로 한다.
- **모든 판정에 근거**: `Decision.trace`에 조건별 평가값과 조항 출처를 남긴다(설명가능성 = 발표 포인트).
- **단위 통일**: 금액은 원 단위 정수, 월 기준. 연 단위 제도(근로장려금)는 변환 함수로 통일.
- **재현성**: 난수 시드, 규칙 버전(git 해시), params 버전을 모든 결과 파일 메타데이터에 기록.
