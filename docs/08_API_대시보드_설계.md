# 08. API · 대시보드 설계

## 1. API (FastAPI, `src/welfaretwin/api/main.py`)
| 메서드 | 경로 | 입력 | 출력 |
|---|---|---|---|
| GET | `/programs` | — | 승인된 규칙 목록(id, 이름, 출처, 상태) |
| POST | `/evaluate` | Household | Decision[] (trace 포함) |
| POST | `/verify/{query}` | query ∈ {blindspot, cliff, overlap}, 옵션 | 반례 목록 + 설명 |
| POST | `/sweep/income` | Household, 소득 범위 | 소득별 가처분소득·제도별 급여 시계열 |
| POST | `/scenario` | 변경안(YAML 또는 자연어) | 영향 지표 + Q4 결과 |
| POST | `/redteam` | 변경안 | 리포트(JSON + Markdown) |
| GET | `/backtest/{id}` | — | 예측 vs 실제 |
| POST | `/extract` | serv_id | LLM 추출 결과·교차검증 상태 |

- 무거운 작업(`/scenario`, `/redteam`)은 결과를 캐시하고, 데모용 입력은 사전 계산본을 즉시 반환한다.
- MVP에서는 Streamlit이 모듈을 직접 호출해도 된다. API는 시간이 남으면 분리한다.

## 2. 대시보드 (Streamlit, `app/dashboard.py`)

### 화면 1. 복지 법전 → 코드
- 좌: 선정기준 원문(지자체 사업 1건) / 우: 추출된 YAML + 교차검증 결과(일치·불일치 하이라이트) + 테스트 통과 수
- 버튼: "다시 추출" (캐시 사용 → 즉시)

### 화면 2. 사각지대 탐지
- "사각지대 찾기" 버튼 → Q1 반례 유형 카드 5~10장(가구 구성 아이콘, 소득인정액, 제도별 탈락 사유 + 조항)
- 상단 카운터: 합성 인구 중 해당 유형 가구 수 추정

### 화면 3. 급여 절벽
- 가구 프리셋 선택(예: "알바 시작한 장애 청년 1인가구") → 소득 슬라이더
- Plotly 그래프: x=근로소득, y=가처분소득, 제도별 급여 누적 영역 그래프, 절벽 구간 빨간 표시
- Q2 결과: "가장 큰 절벽" Top 3

### 화면 4. 정책 시뮬레이터 + 레드팀
- 입력창: 자연어 사업안 → [규칙 초안 생성] → [영향평가 실행]
- 결과: 대상 가구 수·재정·중복률, 새로 포함/탈락 유형, 레드팀 리포트(문서 07 형식)
- 처리 시간 표시(데모 포인트: "30초")

### 화면 5. 백테스트
- B1: 실제 수급자 추이 vs 시뮬레이션 예측 선 그래프, 오차율, 한계 설명

## 3. 디자인 원칙
- 수치 옆에는 항상 출처/조항 링크(설명가능성)
- "단순화 가정" 토글: 화면별로 적용한 가정을 펼쳐 볼 수 있게
- 발표 화면 해상도(1920×1080)에서 스크롤 없이 핵심이 보이도록 구성
