# 08. API · 대시보드 설계

## 1. API (FastAPI, `src/welfaretwin/api/main.py`) — 11/11 구현
웹 데모(https://welfaretwin.vercel.app)가 부르는 실시간 계산 서버. 대시보드·정적 웹과 **같은 엔진·같은 승인 규칙**을 쓴다.
배포: **https://welfaretwin-api.vercel.app** — Vercel Python 함수(정적 웹과 별도 프로젝트 `welfaretwin-api`, 서울 리전 icn1, 1 vCPU·2GB, 최대 120초), `scripts/deploy_api.py --deploy`. Hugging Face Docker Space(`--target space`)는 2026-11 기준 무료 CPU 에 PRO 구독이 필요해(402) 쓰지 않았다. 로컬: `uv run uvicorn welfaretwin.api.main:app --port 7860`. 자동 문서 `/docs`.

| 메서드 | 경로 | 입력 | 출력 | Vercel 실측 |
|---|---|---|---|---|
| GET | `/health` | — | 상태, 규칙 수, 합성 인구 수, 시나리오 표본 수, 현행 생계 선정비율(params), `llm: false`, 버전 | — |
| GET | `/programs` | — | 승인된 규칙 목록(id, 이름, 출처) | — |
| GET | `/regions` | — | 시도·시군구 목록(합성 인구 + 지자체 규칙 지역) | — |
| POST | `/evaluate` | Household | 제도별 자격·급여·탈락 사유, 소득인정액, 기준중위소득, 가처분소득(다른 지역 지자체 사업은 숨김) | 0.1초 |
| POST | `/sweep` | Household, 소득 변동 가구원, 최대 소득(≤600만), 간격(≥1만) | 소득 구간별 제도 급여·가처분소득 — 정적 `sweeps.json` 과 같은 형식·같은 값 | 1.7~2초 |
| POST | `/verify/blindspot` | 빈곤선 비율(20~60%), 제도 조합(생계·기초연금·근로장려금), 개수 | Z3 반례 가구 + 탈락 사유. 없으면 unsat(없음 증명) | 4~13초 |
| POST | `/verify/cliff` | 소득 증가폭 δ, 개수 | Z3 급여 절벽 반례(δ 늘 때 가처분소득 감소), 시간 예산 20초(Vercel)를 제도별로 나눠 탐색 — 실행마다 찾는 절벽이 다를 수 있음 | 18~20초 |
| POST | `/scenario` | 생계급여 선정비율(25~40%), 신청 방식 S0(현행)/S1(자동 안내) | 현행 대비 자격·실수급·재정 변화(합성 인구 1만 가구 표본, 결과 캐시) | 20초(같은 값 0.4초) |

- **공개 서버라 LLM 은 부르지 않는다**(사용자 결정). 규칙 추출·레드팀·에이전트 응답은 캐시·사전 계산본만 쓴다. 그래서 `/extract`·`/redteam`·`/backtest` 는 공개 API 에 두지 않았다(대시보드·웹 사전 계산본에서 보여 줌).
- 무거운 계산(`/verify/*`·`/scenario`)은 한 번에 하나(대기 60초 넘으면 503), IP 당 분당 6회(`WT_HEAVY_PER_MIN`, 넘으면 429). `/sweep` 은 가벼워 제한 없이 최대 600구간만 받는다.
- CORS 는 welfaretwin.vercel.app(+미리보기 도메인)·localhost:8790·`WT_CORS_ORIGINS` 만 허용.
- 시나리오 표본: 1만 가구 표본은 전체 10만 가구 계산과 약 10% 다를 수 있다(생계 35% 시 자격 증가 +19.6만 vs +21.6만). 화면에 "표본 계산"이라고 밝힌다. 발표 수치는 전체 계산본.
- 시나리오 기준선(현행·S0, 같은 표본)은 배포 때 미리 계산해 묶음에 넣고(`artifacts/api/scenario_base.pkl`), 서버 표본과 가구가 같을 때만 쓴다 → 요청마다 변경안만 계산(60초 → 20초).
- Vercel(1 vCPU)에서는 프로세스 풀·시작 예열 없이 계산한다(`VERCEL` 환경 변수로 판단). 결과는 다중 프로세스와 같다(테스트).
- 웹은 `<meta name="wt-api">`(또는 `?api=URL`)로 서버를 찾고, 연결이 안 되면 사전 계산본을 그대로 보여 주며 실시간 버튼만 비활성화한다(연결 재시도 최대 60초).

## 2. 대시보드 (Streamlit, `app/dashboard.py`)

### 화면 1. 복지 법전 → 코드
- 좌: 선정기준 원문(지자체 사업 1건) / 우: 추출된 YAML + 교차검증 결과(일치·불일치 하이라이트) + 테스트 통과 수
- 버튼: "다시 추출" (캐시 사용 → 즉시)

### 화면 2. 사각지대 탐지
- "사각지대 찾기" 버튼 → Q1 반례 유형 카드 5~10장(가구 구성 아이콘, 소득인정액, 제도별 탈락 사유 + 조항)
- 상단 카운터: 합성 인구 중 해당 유형 가구 수 추정

### 화면 3. 급여 절벽
- 가구 프리셋 선택(예: "알바 시작한 장애 청년 1인가구") → 소득 슬라이더
- Plotly 그래프: x=근로소득, y=가처분소득, 제도별 급여 누적 영역 그래프, 절벽 구간 빨간 표시
- Q2 결과: "가장 큰 절벽" Top 3

### 화면 4. 정책 시뮬레이터 + 레드팀
- 입력창: 자연어 사업안 → [규칙 초안 생성] → [영향평가 실행]
- 결과: 대상 가구 수·재정·중복률, 새로 포함/탈락 유형, 레드팀 리포트(문서 07 형식)
- 처리 시간 표시(데모 포인트: "30초")

### 화면 5. 백테스트
- B1: 실제 수급자 추이 vs 시뮬레이션 예측 선 그래프, 오차율, 한계 설명

## 3. 디자인 원칙
- 수치 옆에는 항상 출처/조항 링크(설명가능성)
- "단순화 가정" 토글: 화면별로 적용한 가정을 펼쳐 볼 수 있게
- 발표 화면 해상도(1920×1080)에서 스크롤 없이 핵심이 보이도록 구성
