# 00. 복지트윈(WelfareTwin) 개요

## 1. 문제
- 사회보장 사각지대는 대부분 사건이 알려진 뒤에야 발견된다(비수급 빈곤층 약 73만 명, 2020 기초생활보장 실태조사).
- 사회보장제도 신설·변경 사전협의 접수는 2020년 1,088건 → 2025년 1,610건(한국보건사회연구원 브리프, 2026.5)으로 늘었지만, 제도 간 **중복·누락·급여 절벽**을 사전에 정량 검증하는 도구가 없다.
- 급여 절벽과 오지급 환수(2025년 공공재정 환수 결정 1,296억 원, 환수 건의 73.5%가 오지급형 — 국민권익위원회)는 시행 이후에야 드러난다.

## 2. 해법: 4개 엔진 + 1개 검증
| 레이어 | 이름 | 하는 일 |
|---|---|---|
| L1 | Rules-as-Code 컴파일러 | 복지서비스 선정기준 문서 → 실행 가능한 규칙(YAML DSL) |
| L2 | 형식검증기 | 규칙 전체를 Z3 제약식으로 바꿔 사각지대·절벽·중복의 **반례 가구**를 찾음 |
| L3 | 가상 대한민국 | 합성 가구 10만 개 + LLM 페르소나 에이전트로 신청·근로 행동 시뮬레이션 |
| L4 | AI 정책 레드팀 | 신규 제도 초안을 악용·배제·행정 에이전트가 공격 |
| V | 백테스트 | 과거 제도 변화(2021.10 생계급여 부양의무자 기준 폐지 등) 재현 → 실제 수급 통계와 비교 |

## 3. MVP 범위 (본선 데모용)
- 제도: 기초생활보장 4종(생계·의료·주거·교육), 기초연금, 근로장려금(단순화), 에너지바우처 + 대구·경북 지자체 사업 일부(목표 20건, 최소 5건)
- 인구: 합성 가구 10만 개(전국 분포, 대구·경북 가중 옵션)
- 화면: ①사각지대 지도 ②급여 절벽 그래프 ③신규 사업안 영향평가 ④레드팀 리포트 ⑤백테스트 결과

## 4. MVP에서 하지 않는 것
- 실제 개인정보·행복이음 데이터 연동
- 4,900개 전 서비스 코드화(파이프라인만 시연, 일부 자동 추출 결과를 "검수 대기"로 보여줌)
- 부양의무자 기준의 정밀 모델링(가족 관계 데이터 부재 → 파라미터 근사, 문서화된 한계로 명시)
