# 06. 합성 인구 · LLM 에이전트 · 백테스트 설계 (L3, V)

## 1. 합성 인구 (`population/`)

### 1.1 방법: IPF(반복비례조정) + 조건부 샘플링
1. KOSIS 집계표로 주변분포를 정의한다: 시도 × 가구원수, 가구주 연령대 × 가구원수, 소득구간 분포, 장애인 비율, 점유형태.
2. 시드 테이블(균등)에서 출발해 IPF로 셀 가중치를 맞춘다.
3. 셀별로 가구를 샘플링하고, 구간 내 연속값(소득·재산)은 구간 내 로그정규 분포로 부여한다.
4. 가구원(연령·장애·취업)은 가구 유형별 조건부 분포로 생성한다.
5. 결과 10만 가구. 시드를 고정하고, 대구·경북 가중 버전 옵션을 둔다.

### 1.2 검증
- 주변분포 오차 ±2%p 이내
- 엔진으로 전 가구를 평가한 결과(제도별 대상자 비율)를 실제 수급 통계와 비교 → 차이를 **"자격은 있으나 미신청" 추정치의 근거**로 사용

### 1.3 한계(발표에서 명시)
- 집계표 기반이라 재산·소득의 결합분포가 거칠다 → 2단계에서 한국복지패널·MDIS 마이크로데이터(차등프라이버시) 적용

## 2. 페르소나 에이전트 (`agents/`)

### 2.1 비용을 위한 구조
가구 10만 개에 LLM을 직접 호출하지 않는다.
1. 가구 특성(연령 구성, 소득 구간, 장애, 지역 유형, 디지털 역량 프록시=가구주 연령, 근로 여부)으로 **k≈200 클러스터**를 만든다.
2. 클러스터 대표 프로필 → 페르소나 서술(자연어)로 만든다.
3. 페르소나 × 시나리오마다 LLM에 질의하고 **행동 확률**을 JSON으로 받는다.
4. 확률을 클러스터 소속 가구 전체에 적용하고 몬테카를로로 집계한다.

### 2.1b 가상 국민 — 클러스터마다 통계 기반 가상 개인 3명 (v2, 11/11)
v1 은 LLM 에게 '가구주 20대, 1인 가구, 소득 1분위…' 같은 **집단 설명**을 주고 3번 물었다. v2 는 그 집단 조건에 맞는
**가상 개인 3명**이 각자 1인칭으로 답하고, 클러스터 확률 = 3명 평균이다(제안서의 '1,000명 생성형 에이전트' 방식).
- 인물: [NVIDIA Nemotron-Personas-Korea](https://huggingface.co/datasets/nvidia/Nemotron-Personas-Korea)
  (2026-04, CC BY 4.0, KOSIS·대법원·건보공단 통계 기반 합성 100만 명 — 실제 개인 아님). 첫 조각(111,112명)만 쓴다(`data/raw/nemotron`, 커밋 안 함).
- 매칭(`population/residents.py`, 결정적 — 해시 순서): 나이(클러스터 가구주 연령대), 가구 형태(가구원 수에 맞는 Nemotron family_type,
  가구주·배우자일 가능성이 큰 유형만), 취업(3명 중 취업자 수 = round(3 × 가구주 취업 비율)), 지역(클러스터 시도 분포를 3자리에 배정),
  [가정] 소득 1~2분위에는 고소득 전문·관리직 직업을 고르지 않음. 238개 클러스터 × 3명 = 714명 모두 조건 완화 없이 매칭, 중복 인물 0.
- 경제 상황(소득·주거 점유·장애·노인·아동)은 Nemotron 에 없으므로 **합성 인구(클러스터) 값이 정답**이고 프롬프트에
  "실제 상황 — 인물 소개와 어긋나면 이것을 따르라"로 넣는다. Nemotron 은 변수를 서로 독립으로 뽑았다고 밝히므로(데이터 카드)
  인물 묘사와 경제 상황이 어긋날 수 있다 — 그래서 '사람'(성격·가족·지역·직업)만 맡긴다.
- 프롬프트 `behavior-v2-resident`, 출력 스키마는 v1 과 같음(rationale 은 1인칭). 응답 캐시 `.cache/llm/`. v1 은 `--agents cluster` 로 재현,
  v1 결과는 `artifacts/demo/agents_v1/`, 응답은 `artifacts/sim/behavior_v1.parquet`.
- 보정(§2.3)·시나리오·백테스트는 그대로 — 행동 응답만 바뀐다. 두 버전 비교는 `reports/eval_*.md` §4.

### 2.2 질의 형식 (구조화 출력)
```json
{
  "apply_probability": 0.0-1.0,          // 자격이 있을 때 실제 신청할 확률
  "reasons": ["정보 부족", "낙인감", ...],
  "work_change": {"hours_delta_per_week": -10..10, "prob": 0.0-1.0},  // 절벽 인지 시 근로 조정
  "channel": "온라인|주민센터|안내문 수신 후"
}
```
- 프롬프트에 시나리오 정보(자동 안내 여부, 신청 절차 수, 급여액 변화)를 넣는다.
- 캐시 키: (persona_id, scenario_hash, 프롬프트 버전, 모델명). 온도는 낮게 두고 3회 샘플 평균을 쓴다.

### 2.3 보정 (가장 중요)
LLM 확률은 그대로 믿지 않는다.
- 기준 시나리오(현행)에서 시뮬레이션 실수급자 수가 실제 수급자 수에 맞도록 **클러스터 공통 보정 계수**(로지스틱 절편)를 1개 학습한다.
- 변경 시나리오에는 같은 보정을 적용한다 → LLM은 "변화의 방향과 상대 크기"를, 보정은 "수준"을 담당한다.

### 2.4 시나리오 엔진 (`sim/scenario.py`)
입력: 규칙 세트 R(현행/변경), 행동 모듈 on/off
출력 지표:
- 자격 대상 가구 수, 실수급 가구 수(행동 반영), 미신청 사각지대 규모
- 월 재정 소요(급여 합계)
- 새로 포함/새로 탈락 가구 유형 상위 10개(문서 05 Q4와 연결)
- 절벽 노출 가구 수

## 3. 백테스트 (`backtest/`)

| 시나리오 | 내용 | 비교 기준 | MVP 처리 |
|---|---|---|---|
| B1 | 2021.10 생계급여 부양의무자 기준 폐지(고소득·고재산 예외 유지) | 수급자 2020년 213만 → 2021년 236만(e-나라지표) | 부양의무자 기준을 "가구별 탈락 확률 파라미터"로 근사, 폐지 시 해제 |
| B2 | 기준중위소득 연도별 인상 | 연도별 수급자 수 | 연도별 params로 재평가 |

- 지표: 증가분 예측 오차율 = |예측 증가 − 실제 증가| / 실제 증가 (목표 ±10%, 달성 못하면 그대로 보고)
- 실제 증가에는 다른 요인(코로나19 등)이 섞여 있다는 점을 화면과 발표에서 명시한다.
