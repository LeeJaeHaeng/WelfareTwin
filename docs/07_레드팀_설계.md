# 07. AI 정책 레드팀 설계 (L4)

## 1. 목표
신규·변경 제도 초안을 출시 전에 공격해 **악용 경로, 배제 경로, 행정 부담**을 리포트로 낸다.
사용 장면: 지자체 담당자가 사전협의 전에 사업안을 넣고 리포트를 받는다.

## 2. 입력
- 자연어 사업안(예: "대구 ○○구 65세 이상 단독가구에 월 5만원 난방비 지원, 기준중위소득 60% 이하") → L1 추출기로 규칙 초안 생성
- 또는 YAML 규칙 직접 입력

## 3. 에이전트 3종
| 에이전트 | 방법 | 출력 |
|---|---|---|
| 배제 에이전트 | Z3 Q4(새로 탈락)·Q1(사각지대)을 변경안 포함 세트로 실행 + 경계 근처 가구 열거 | "취지상 대상인데 탈락하는 가구 유형" Top N |
| 악용 에이전트 | 조작 가능한 변수 집합(세대 분리, 소득 신고 시점, 재산 형태 전환)을 정의 → Z3로 "작은 조작으로 자격을 얻는 가구" 탐색 | "형식 요건 조작으로 수급 가능한 경로" + 위험도 |
| 행정 에이전트 | 규칙의 조건 수, 필요 증빙(LLM이 원문에서 추출), 기존 제도와의 중복 확인 단계 수 | 담당자 처리 단계 추정, 중복 확인 필요 제도 목록 |

- LLM은 조작 가능한 변수 후보 제안과 리포트 문장 작성에만 쓴다. 경로의 존재 여부는 Z3가 판정한다.
- 악용 경로는 **방어 목적의 설계 점검**으로만 서술한다(구체적 실행 방법이 아니라 "규칙상 허점 + 보완안" 형식).

## 4. 리포트 형식
```
[정책 사전 점검 리포트] ○○구 어르신 난방비 지원(안)
1. 영향: 대상 가구 ○○천 / 월 재정 ○○백만원 / 기존 에너지바우처와 중복 ○○%
2. 배제 위험: 2인 노인가구(배우자 64세) 탈락 → "단독가구" 정의 확인 필요
3. 허점 위험: 세대 분리 시 요건 충족 가능 → 실거주 확인 조건 추가 권고
4. 급여 절벽: 중위 60% 경계에서 월 5만원 일시 소멸 → 점감 구간 권고
5. 행정 부담: 필요 확인 ○단계, 중복 확인 대상 제도 ○개
근거: 각 항목의 반례 가구·조항 출처 첨부
```

## 5. 구현 순서
1. 배제(Q4 재사용) → 2. 절벽(Q2 재사용) → 3. 중복 → 4. 악용(시간 남으면) → 5. 리포트 템플릿
