# 09. 테스트 · 검증 계획

## 1. 테스트 계층
| 계층 | 대상 | 방법 | 통과 기준 |
|---|---|---|---|
| 단위 | DSL 파서, 표현식 화이트리스트, income 모듈 | pytest | 100% |
| 규칙 정답 | 수작업 규칙 7종 | `tests/rules/*.yaml` 가구→기대값 | 30케이스 이상 전부 통과 |
| 경계값 | 모든 승인 규칙 | 자동 생성(선정선 −1/0/+1) | 전부 통과 |
| 속성 | 소득인정액 단조성, 급여 비음수 | hypothesis | 반례 없음 |
| 엔진–Z3 일관성 | 평가기 vs Z3 모델 | 무작위 가구 1,000개 | 100% 일치 |
| LLM 추출 | 지자체 사업 | 교차검증 일치율, 인용 부분문자열 검사, 사람 검수 | 일치율·수정 건수 기록 |
| 합성 인구 | 주변분포 | 집계표 대비 | ±2%p |
| 시뮬레이션 보정 | 현행 실수급자 수 | 실제 통계 대비 | 보정 후 ±5% |
| 백테스트 | B1, B2 | 증가분 오차율 | 목표 ±10% (미달 시 그대로 보고) |
| 데모 | 시나리오 전체 | 수동 리허설 | 3회 연속 무오류, 각 화면 30초 이내 |

## 2. 기록
- `reports/eval_YYYYMMDD.md`: 각 지표 값, 규칙/params/모델 버전
- 발표 슬라이드의 모든 수치는 이 리포트에서만 가져온다.

## 3. 회귀 방지
- params 값 변경 시 규칙 정답 테스트 전체 재실행
- 프롬프트 버전 변경 시 LLM 추출 일치율 재측정
